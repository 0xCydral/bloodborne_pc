# Handoff: resume after the migration

Read `MIGRATION.md` on this branch first. It holds the inventory: what was
kept, what can be skipped, the `C:\` references to fix for Linux, and the
resume commands. This file covers what MIGRATION.md does not: the open work
and the decisions behind it.

## Goal

A native PC port of Bloodborne (CUSA03173) with upscaling (FSR, HelixSR) and
a launcher, released as betas on `github.com/0xCydral/bloodborne_pc`. A side
app, AMDLSS (`github.com/0xCydral/AMDLSS`, Windows-only), installs HelixSR and
OptiScaler into any DX12 DLSS game.

   run.

- The HelixSR bridge is D3D12 and `#ifdef _WIN32`; it drops out of the Linux
  build. Plan: no HelixSR on Linux.
- AMDLSS is a Windows app (PyInstaller exe, Windows game paths). Plan: develop
  it only after a Windows install returns, or in a VM.
- `msys2-env.sh` and `packaging/windows/` are Windows packaging. Use
  `build.sh` and `shell.nix` instead.
- The Windows release builds (`windows-v*`) need Windows or CI; build them on
  GitHub Actions.

## Decisions

- The HelixSR Vulkan-to-D3D12 bridge is Windows-only (`#ifdef _WIN32`). On
  Pop!_OS the port builds without it; HelixSR is out of scope on Linux.
- DLSS frame generation inside AMDLSS uses OptiScaler with `FGInput=dlssg`,
  `FGOutput=fsrfg`. Upgrading to FSR 4.1.1 frame generation was proposed and
  the user dropped it ("no, nevermind then").
- Toggling frame generation mid-game crashed in our runs; the user said not to
  chase it.

## Wrong paths, do not retry

- HTML or code mockups for the concept designs.
- Parsing robocopy output with the English `Bytes :` pattern; this machine's
  Windows was Spanish-locale (`Bytes:`, `Archivos:`). Moot on Linux.
- Robocopy with a `/LOG` path whose folder does not exist: exit 16, nothing
  copied.
- Python edits through a bash heredoc: backslash escapes get mangled. Use the
  file tools.
